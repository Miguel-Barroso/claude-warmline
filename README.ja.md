**Claude Code のためのプロンプトキャッシュ・オブザーバビリティと監査。**

Claude Code は毎ターン、会話全体を送り直しています。それを現実的なコストに保って
いるのがサーバー側のプロンプトキャッシュです。キャッシュが生きている間、各ターンは
通常の入力価格の約 **0.1 倍**で会話を*読み取り*ます。消えた瞬間、次のターンは約
**2 倍**を払って作り直します。Claude Code はこれをすべて把握していて、訊けば答えます
— `/usage` は現在のキャッシュ状態を表示し、v2.1.251 以降はステータスラインに渡される
データにも含まれています。していないのは、それを常に目の前に置いておくことと、先月の
セッション全体で冷えたことがいくらかかったのかを教えることです。warmline はその両方を
やります — Claude Code 自身のキャッシュの真実をステータスラインに載せ、履歴をローカル
で監査します。読むのは Claude Code がすでにあなたのマシンに記録しているデータだけ。
依存関係は `python3` と `bash` のみ、外部への送信はゼロです。

![ステータスラインの 5 つの状態: 失効時刻を伴う緑の cache HOT、失効が近づいたときの黄色い cache HOT、赤の cache COLD、そして Claude Code がキャッシュ情報を返さないときの淡色の cache off と cache ?](docs/statusline.svg)

## 何をするツールか

**観測 (Observe) → 説明 (Explain) → 測定 (Measure) → 緩和 (Mitigate)。**

| | | |
|---|---|---|
| **観測** | `warmline` ステータスライン | キャッシュが今どうなっているか |
| **説明** | `warmline audit` | あるセッションで何が起きたかを、ターンごとに |
| **測定** | `warmline audit --all` | このマシンの全セッションで、損失がどこに集中しているか |
| **緩和** | `warmline keep-warm` | *任意*: 防げる失敗モードをひとつだけ防ぐ |

最初の 3 つは読み取り専用の観測であり、このプロジェクトの本体です。4 つ目はオプト
イン、既定でオフ、そして意図的に境界が引かれています — 下の「任意: キープウォーム」
を参照してください。

## インストール

```sh
curl -fsSL https://raw.githubusercontent.com/Miguel-Barroso/claude-warmline/main/install.sh | bash

warmline status              # 何がインストールされ、有効か
warmline audit               # このプロジェクトの直近セッションを、ターンごとに
warmline audit --all         # このマシンの全セッションを、並べ替えて
warmline watch               # 全セッションの温度を、ライブで、ctrl-c まで
```

## なぜ重要なのか

Claude はメッセージ間で何も覚えていません。Enter を押すたびに、Claude Code は
これまでの会話*全体* — システムプロンプト、ツール、読み込んだすべてのファイル、
すべての返答 — を再送信します。長いセッションでは毎ターン 10 万トークン超の入力に
簡単に到達します。

プロンプトキャッシュがそのコストを吸収しますが、**約 1 時間の無操作**で取り壊され、
会話の冒頭が書き換えられた瞬間にも消えます (`/compact` も自動コンパクションもそう
します)。昼食から戻って大きなセッションを開けば、次の 1 メッセージが再構築コストを
丸ごと支払います — よりによって、答えが一番欲しい瞬間に。

ここに書かれていることはすべて 10 万トークン超のための話です。2 万トークンなら、
冷えても作り直しは安く済みます。

## 観測: ステータスライン

```
Fable 5 | claude-warmline | ctx 43% (168k) | cache HOT (cold ~13:04)
```

| フィールド | 意味 |
|---|---|
| `ctx 43% (168k)` | コンテキストウィンドウの使用率 — 80% を超えると黄色。自動コンパクションはそこから前置きを書き換えます |
| `cache HOT (cold ~13:04)` | キャッシュされた前置きは温かく、表示時刻に TTL を抜けます。失効の 15 分前からは同じ文言のまま黄色になります |
| `cache HOT 5m` | 同上、5 分 TTL の場合 — 従量クレジット、API キー、クラウドプロバイダー。1 時間の場合が既定なので、そちらには印を付けません |
| `cache COLD` | 前置きは TTL の外にあり、次のターンがそれを作り直します |
| `cache off` | プロンプトキャッシュが無効か、このプロバイダー/ゲートウェイがキャッシュトークンを報告しません。ここは待っても温まりません |
| `cache ?` | キャッシュ情報がありません — v2.1.251 より前の Claude Code か、セッション最初の API 応答より前です |

**これらはすべて Claude Code が報告した値であり、warmline の推測ではありません。**
v2.1.251 以降、ステータスラインに渡されるデータにはキャッシュの実際の温度・TTL・
失効時刻が含まれます。warmline はそれを読むだけで、ターン間の間隔を計って当てにいく
ことはもうしません。`COLD`・`off`・`?` を分けているのは意図的です — 「キャッシュが
失効した」「キャッシュ自体が行われていない」「warmline からは見えない」は別々の事実
であり、これらをひとつに丸めることが、キャッシュ計器が嘘をつき始める入り口だからです。

失効時刻は常に絶対的な壁時計表示で、カウントダウンではありません — 止まった
カウントダウンは*誤り*ですが、止まった時計は今でも*真*だからです。`HOT` から `COLD`
への切り替えは、Claude Code 自身が失効のその瞬間にステータスラインを再描画して
行います。インストーラーが書き込む 60 秒の更新間隔はそのためではなく、**失効前の
黄色い警告をアイドル中にも見せる**ためにあります。それがなくても表示は正しいまま
ですが、先に警告してくれなくなります。

[全フィールド・色・トラブルシューティング →](docs/STATUSLINE.md)(英語)

### 冷えて戻ってきたとき

キャッシュはもうありません。次に何をしても、そのコンテキストは一度だけ未キャッシュ
価格で処理されます。問題は、その 1 回で何を買うかだけです。

- **会話の履歴がまだ必要 →** `/compact`。高価な処理はどのみち発生します。それなら
  要約を作らせて、以後は安く持ち運びましょう。
- **状態が会話の外にある** (メモリファイル、計画ドキュメント、コード) **→**
  `/clear`。要約のための 1 回すら省けます。
- **コンテキストが小さい →** 何もしない。2 万トークンの再構築は安いものです。
- **`HOT` のときにコンパクトしてはいけません** — コンテキストウィンドウが満杯の
  場合を除いて。約 2 倍を払って築いたキャッシュを自ら壊す行為です。

[完全な理由づけ →](docs/AUDIT.md#when-you-come-back-cold)(英語)

## 説明と測定: 監査

`warmline audit` は、Claude Code が記録済みの各 API リクエストに書き残した使用量
フィールドで採点します — ステータスラインと違い、1 ターンの遅れはありません。
`--all` は同じことをこのマシンの全セッションに対して行い、並べ替えます。(実行される
のはインストール済みの `warmline-audit` コマンドです。どちらの綴りでも動くので、
既存のスクリプトはそのまま使えます。) 以下はあるマシンの 8 週間の履歴に対する実際の
出力です:

```
$ warmline-audit --all --price 3
147 sessions under /Users/mb/.claude/projects  (13 more without API turns; ttl per session from its cache buckets, 60m fallback)

cache health  █████████████████████████░  95% hot  (10,394 of 10,921 turns)
cold events   198  (159 rebuilt, 39 ttl) -- 1.8% of all turns

start        project                 turns    hot  part  rebuilt   ttl  avoidable cold  share    premium
08-07 14:30  MimirBlue                 201    189     6        4     2       1,294,770    11%      $7.38
   ⋮
TOTAL                                10921  10394   329      159    39      12,134,109   100%     $69.16

where the cold came from
  unknown             ██████████████████████████  92 (39%)
  session start       █████████████████  59 (25%)
  auto-compact        ██████████  37 (16%)
  inactivity          █████████  31 (13%)

estimated avoidable premium ~$69.16  (top 5 sessions: $21.36, other 142: $47.81)
```

冷えたターンには、記録から**証明できる**範囲で原因が付きます — `/compact`、
`auto-compact`、`model change`、`inactivity`。それ以外はすべて `unknown` に入ります
が、これは**残余の受け皿であって、発見ではありません** — 記録に証拠がないので、
warmline は原因を名指ししないだけです。Anthropic は、記録には決して現れない前置き
無効化の操作をいくつも挙げています — 努力レベルの変更、fast モードの有効化、ツール
全体の拒否、プラグインの有効化/無効化、前置きにツールを読み込む MCP サーバーへの
接続、そして Claude Code 自体のアップグレード。どれもここに落ちます。セッション途中の
CLAUDE.md 編集は該当しません: Anthropic はそれをキャッシュが*保たれる*操作として
挙げています。このマシンでは `unknown` がコールドの 39% を占め、あらゆるコンパク
ションの合計を上回り、最悪の 1 セッションだけで全体の 11% です — これは「最大の割合が
未説明である」と読むべきもので、診断ではなく、調べる理由です。(判定は記録された
使用量に基づきますが、`COLD(rebuilt)` と `COLD(ttl)` の切り分けは TTL 次第です — TTL
はセッションごとに、そのキャッシュバケットの記録から自動検出されます。)

**これらの金額は、あなた自身の記録に残るトークン数から算出した損失の推定であり、
請求データではありません** — warmline は Anthropic が実際にいくら請求したかを見て
いませんし、見ることもできません。レポート最終行のラベルは
`estimated avoidable premium` で、そこでの「avoidable (避けられる)」は*各セッション
で避けようのない最初の書き込みを除いた*という意味だけを持ちます。実際には防げない
ものも含まれます — 例えばノートを閉じている間に起きた TTL 失効です。入力と出力は
別々の単価で計算されます。Claude の課金がそうなっているからです — `--price` は
モデルの基本**入力**価格 ($/MTok。キャッシュの経済はすべてこちら側です)。出力
トークンはキャッシュされないので、監査はそれを別行に出します。温めれば節約できる
かのように見せることはしません。

監査が過去を採点するのに対し、**`warmline watch`** は現在を映します — 全セッション
の温度のライブビューで、ctrl-c まで再描画を続けます。デスクトップアプリのセッション
もそこに現れます。ステータスラインは描画できなくても、書き出す記録ファイルは同じ
だからです。

## 任意: キープウォーム

ここまではすべて観測です。キープウォームは任意の 4 つ目の機能です —
`~/.claude/CLAUDE.md` に置かれる短い指示ブロックで、長く静かな待ち時間の間、約 50
分ごとにセッションへ ping するようエージェントに伝えます。結果が返ってきたとき、
キャッシュがまだ温かいように。

```sh
warmline keep-warm on        # 既定でオフ。グローバル。いつでも取り消せます
warmline keep-warm status    # ON / OFF / INCONSISTENT (終了コード 0 / 1 / 2)
```

**デーモンではありません** — cron もバックグラウンドプロセスもなく、実行中の
Claude Code セッションの外でリクエストを送ることもありません。バックグラウンド
タスクがすでに無料でキャッシュを温めているときはスキップし、コンテキストが小さい
ときもスキップし、作業が再開した瞬間に止まり、約 10 時間で諦めます。ping の 1 回
1 回はあなた自身のプランに対する通常の課金リクエストです。高価な再構築 1 回を安い
読み取り数回と交換するだけで、どんな制限も迂回しません。

[何であり何でないか・`wait-for`・ノースリープモード・限界・利用規約の検討 →](docs/KEEP-WARM.md)(英語)

## どこで動くか

| フロントエンド | ステータスライン | `warmline audit` / `watch` | keep-warm |
|---|---|---|---|
| ターミナル CLI | ✅ | ✅ | ✅ |
| デスクトップアプリ (ローカルの Code タブ) | ❌ | ✅ | ✅ |
| VS Code / JetBrains パネル | ❌ | ✅ | ✅ |
| クラウド / Cowork セッション | ❌ | ❌ | ❌ |

ローカルの GUI フロントエンドはカスタムステータスラインを描画しません
([要望は提出済み](https://github.com/anthropics/claude-code/issues/41456))。
ただし同じエンジンをローカルで動かし、同じ `~/.claude` を共有し、同じ記録ファイルを
書き出すため、監査ツール・`warmline watch`・キープウォームポリシーはそこでも普通に
動きます。**例外はクラウド / Cowork セッションだけで、warmline はその一部たりとも
届きません。**

[完全な対応表と検証方法 →](docs/SURFACES.md)(英語)

## 実測による裏付け

- **50 分アイドル: 温かい。70 分: 冷たい。** 干渉のない環境での 2 系統プローブで、
  50 分後のプローブは 71,312 トークンの前置きを丸ごと読み戻し、70 分後は 45,033
  トークンを書き直しました。1 時間の TTL は実在し、読み取りはそれを更新します。
- **147 セッション・10,921 ターンの監査** (同じマシン): 95% が hot。ただしコールド
  イベントの 39% は原因を**特定できていません** — 記録に証拠がなかった残余であって、
  名前の付いた原因ではありません。
